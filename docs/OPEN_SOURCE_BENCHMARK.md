# DocAlign 开源方案对照与演进决策

更新日期：2026-08-25

## 目标

这份记录用于说明 DocAlign 从相似开源项目中吸收了哪些工程思想、哪些能力已经独立实现，以及哪些方案因安全性、维护性或产品定位原因没有直接采用。外部仓库仅作为设计与验证参考，DocAlign 没有复制第三方实现代码。

## 对照结论

| 项目 | 值得借鉴的能力 | DocAlign 的独立实现 | 未直接采用的部分 |
| --- | --- | --- | --- |
| [paper_format_agent](https://github.com/zxyasfas/paper_format_agent) | 格式化前后内容指纹、保存前阻断、标记优先的语义判定 | 原文/表格/页眉页脚/图片/关系指纹；受保护 XML 部件哈希；失败不发布输出 | 不依赖单一论文模板，不把语义判断完全交给模型 |
| [format-thesis-docx](https://github.com/wksudud/format-thesis-docx) | 规则编号、期望值、实际值、证据和变更清单 | `format-manifest.v1` 与 `compliance-report.v1`，要求使用 R0001 编号并保留来源部件和证据 | 不把 PDF 视觉结果当作唯一真相；OOXML 验证仍是硬门槛 |
| [Word-Formatter-Pro](https://github.com/cwyalpha/Word-Formatter-Pro) | 表格内全文格式化、重复表头、行高和自适应列宽 | 表格字体/字号/强调/颜色、边框、对齐、表头重复、行不可拆分和单元格对齐的落盘重开验证 | 不重建表格，避免破坏合并单元格、嵌套表格和关系 |
| [docxengine](https://github.com/ruwadgroup/docxengine) | 确定性 OPC/ZIP 操作、稳定锚点、始终开启的验证器 | `p1`、`t1.r2.c3.p1.r1` 等稳定定位符；受保护包部件校验；原子发布 | 现阶段不另造完整 OOXML DOM/OPC 引擎，继续利用成熟库并在必要处做 XML 级补丁 |
| [docx-cli](https://github.com/kklimuk/docx-cli) | 面向代理的可寻址对象、原位 XML 修改 | 文档结构、计划、变更和错误共享稳定 locator | 暂不引入通用编辑命令语言，先确保格式化场景收敛 |
| [gongwen-skill](https://github.com/linhut/gongwen-skill) | 从样本文档提取样式画像、规则分层和严重级别 | 可导出的格式画像，区分自动可用规则与仅供参考的样例证据 | 不自动把单一样本文档的偶然直接格式提升为全局规则 |
| [word-format-checker](https://github.com/hjbjltnc/word-format-checker) | 只检查不修改、问题位置报告、表格检查 | 网站中的“只做格式体检”，不生成任务、不写源文件 | 不把检查逻辑绑定到桌面 Word 或单一模板 |
| [format-thesis-docx-skill](https://github.com/h46373824-tech/format-thesis-docx-skill) | 基于证据的要求清单、确认项和清单式工作流 | 机器可读格式画像、合规报告和明确的未支持/假设边界 | 暂不要求安装 Word 加载项，保持浏览器与本地 API 的轻量架构 |

## 本轮已经落地

### 1. 稳定位置编号

- 正文段落：`p1`、`p2`。
- 表格：`t1`；表格单元格内文字可定位到 `t1.r2.c3.p1.r1`。
- 分节：`s1`；页眉页脚使用 `s1.header.default` 等形式。
- 位置编号进入分析结果、格式计划、变更记录、警告和验证问题，方便 UI、API、人工复核和后续代理操作使用同一坐标。

### 2. 只读格式体检

- `POST /api/v1/documents/{document_id}/compliance`
- 输入当前 `analysis_id` 与 `spec_id`，只比较，不修改源文件，也不创建格式化任务。
- 返回问题总数、严重级别和错误码统计、受影响位置数，以及最多 250 条带 locator 的问题。

### 3. 表格闭环验证

输出文件保存后重新打开并验证：

- 表格整体对齐和网格边框；
- 重复表头与行不可跨页拆分；
- 单元格垂直对齐；
- 所有非保护文字的中西文字体、字号、强调和清理后的颜色；
- 合并单元格按 OOXML 单元格对象去重，避免漏检或重复处理。

### 4. 可导出的格式画像

- `GET /api/v1/documents/{document_id}/format-manifest`
- 从 `styles.xml`、`document.xml`、`numbering.xml` 和页眉页脚部件提取可追溯要求。
- 每条要求包含编号、分类、目标、属性、期望值、来源部件、文本证据、置信度和是否可自动应用。
- 样式和分节中的确定值可作为自动规则候选；表格样例和页眉页脚样例默认只作为证据，防止把偶然格式误当模板规范。

### 5. 更严格的内容安全门

除正文、表格、页眉页脚、图片、关系和未知顶层结构外，验证器现在还保护：

- 批注及相关 XML；
- 脚注、尾注和人员信息；
- `customXml`；
- glossary 部件。

这些内容若在格式化过程中发生未授权变化，输出会被阻止，不会替换或发布为最终文件。

## 后续路线

1. 将格式画像中的“自动可用”规则通过人工确认转成 FormattingSpec，而不是直接套用。
2. 增加两份文档之间的格式画像差异报告，用于模板迁移和批量验收。
3. 把合规报告的 locator 与浏览器预览联动，点击问题直接滚动到对应段落或表格。
4. 为目录、脚注、尾注、批注和文本框建立专门的格式规则，而不是仅做内容保护。
5. 在已加入公文主体与两所高校公开规范参考子集的基础上，继续补齐机构模板、规范更新监测、审批
   与签名发布；公文、论文、合同、财务宽表等规则保持独立版本、来源和变更历史。
