# DocAlign 网站使用说明

适用版本：DocAlign 0.1.0（2026-08-30 界面）

DocAlign 用于整理 Word 文档格式：先识别标题、正文、表格等结构，再按选定规则排版并验证。源文件不会被覆盖，处理完成后会生成新的 DOCX 文件。

## 一、打开网站

本地服务启动后，在浏览器访问：

<http://127.0.0.1:3000>

页面右上角显示“本地处理”时，文档、分析结果和输出文件均保存在本机。网站支持：

- 上传 `.docx` 文件，默认最大 20 MB；
- 粘贴纯文本并生成 Word 草稿；
- 结构分析、格式体检、自动排版和结果审计。

> “智能分析”和“自然语言编译”需要管理员先配置兼容模型。未配置模型时，其余功能仍可正常使用。

## 二、最快使用流程

1. 上传 Word 文档，或粘贴纯文本生成草稿。
2. 点击“分析结构”。
3. 检查左侧识别出的标题、正文等角色，必要时手动修正。
4. 在右侧选择一个通用整理方案或官方规范参考包。
5. 如需先查看问题，点击“只做格式体检”。
6. 点击“自动排版并验证”。
7. 任务完成后，先点击“查看格式前后对照”复核，再下载格式化 DOCX，并按需查看审计结果。

如果需要用同一规则处理多份文件，先保存规则包，然后点击右上角“批量处理”。

## 三、详细操作

### 1. 导入文档

有两种方式：

- **上传 Word**：把 `.docx` 拖入上传区，或点击“选择文件”。
- **粘贴纯文本**：点击“粘贴纯文本”，填写文件名和内容，再点击“生成 Word 草稿”。

粘贴纯文本时，每行会生成一个段落，还可以使用简单标记：

```text
# 文档标题
## 一级标题
这是正文内容。
- 这是列表项
```

导入后，中间区域会显示浏览器预览。此预览仅供快速检查，最终效果请以下载后的 Word 文件和审计结果为准。

### 2. 分析文档结构

- **分析结构**：推荐默认使用。它在本地确定性识别主标题、各级标题、正文、列表、图表题、参考文献等内容。
- **智能分析**：适合结构复杂或识别结果不理想的文档。点击后会出现确认提示；确认后，段落文字和格式摘要会发送到已配置的兼容模型端点，DOCX 文件、图片和密钥不会发送。

分析完成后，左侧“文档结构”会显示每段内容、位置编号、识别置信度和角色。
顶部的复核栏会统计真正需要人工判断的段落；空段落不会计入待确认数量。文档较长时，可点击
“仅看待确认”快速聚焦。

结构列表上方还会显示“文档处理范围预检”。字段、公式、内容控件、复杂表格、文本框、脚注尾注、
批注、嵌入对象、外部链接关系和未知 Word 结构会分别说明实际处理方式；“保留并验证”不等于完成
专门格式化。如果预检显示“需确认”，请展开位置和处理方式，并勾选“我已了解这些复杂内容需要在
Word/WPS 中逐项核对”后再排版。仅有页眉页脚字段、普通图片或多分节等已支持提示时不会增加确认
步骤。这个确认不只控制页面按钮：本地服务在创建任务时会再次校验，因此脚本或 API 客户端也不能
绕过；如果分析结果要求确认，请在 `POST /api/v1/jobs` 中提交
`processing_boundary_acknowledged: true`。
命令行使用者应先运行 `docalign analyze` 查看同一清单；存在需核对内容时，`docalign format` 必须
显式增加 `--acknowledge-processing-boundary`，否则不会生成输出。

### 3. 检查和修正文档角色

检查左侧每一段的角色，例如“主标题”“一级标题”“正文”“列表项”或“参考文献条目”。如果识别不正确，直接在该段右侧的下拉框中选择正确角色，系统会立即保存修正。

建议重点检查：

- 主标题和各级标题是否对应正确；
- 摘要、关键词、图题、表题是否被正确识别；
- “待确认”段落是否需要改为正文或其他角色；
- 参考文献和附录是否被正确区分。

### 4. 选择格式规则

#### 默认整理模式

适合大多数用户，不需要配置模型。目录分为“通用整理方案”和“官方规范参考包”。系统只会按分析
结果推荐通用方案；参考包必须由用户主动选择。

通用整理方案用于快速统一观感：

| 整理方案 | 适用场景 | 主要特点 |
| --- | --- | --- |
| 常规文档 | 通知、论文、普通报告 | A4 竖版、正文小四、1.5 倍行距 |
| 紧凑信息 | 简历、会议纪要、操作手册 | 较紧凑、左对齐、节省页面空间 |
| 合同条款 | 合同和条款型文档 | 条款标题左对齐，保持连续阅读 |
| 宽表优先 | 财务报表、多列表格 | 保留必要横版分节，自适应表格宽度和字号 |

四个通用方案都会统一可见文字颜色、清除高亮和底纹，并启用内容保护与结果验证。

方案列表下方会显示“规则来源与适用边界”，包括规则包版本、维护方、复核日期、能力覆盖和已知
限制。通用方案都标记为“通用方案 · 非机构合规”，不能替代 GB/T 9704、学校、期刊或单位内部的
正式模板。

官方规范参考包当前包括：

| 参考包 | 自动执行的主要范围 | 仍需人工处理 |
| --- | --- | --- |
| GB/T 9704—2012 主体参考 | 页面版心、主体标题与正文字体段落 | 版头、版记、印章、奇偶页码和完整发文要素 |
| 南开大学论文 2026 参考 | 页面边距、四级标题、正文、图表题、参考文献与附录文字 | 封面、目录、动态篇眉、分节页码和摘要标题语言差异 |
| 北京印刷学院硕士论文 2025 参考 | 页面边距、三级标题、正文、图表题、参考文献与附录文字 | 官方模板、装订线、动态页眉、分节页码和三线表细节 |

每个参考包都会显示公开来源链接、规范版本、逐条覆盖状态和自动验收证据。覆盖状态分为：

- **自动执行**：系统会设置对应格式，并在生成后重开 DOCX 验证；
- **人工复核**：系统保留或部分处理，用户必须在 Word/WPS 中核对；
- **暂不支持**：当前不会生成或校对该项。

选择参考包后，“自动结构排版”默认关闭，避免学校或公文规范意外改变文档结构。先阅读全部条款和
限制，再勾选“我已查看自动、人工和暂不支持条款”；确认前“格式化并验证”按钮保持禁用，但仍可
点击“只做格式体检”。参考包是依据公开规范整理的可执行子集，未经标准或学校发布机构审核、授权
或背书；即使自动验证通过，也不能据此宣称整份文档已经完整合规。

#### 自然语言编译

需要先完成结构分析，并且管理员已配置兼容模型。

1. 切换到“自然语言编译”。
2. 输入要求，例如：“全文中文宋体，英文 Times New Roman；正文小四、1.5 倍行距；一级标题黑体三号居中。”
3. 选择是否启用“智能排版设计体系”：
   - 勾选：先设置完整的页面、标题、正文、列表和题注体系，再用你的要求覆盖对应部分；
   - 不勾选：只处理明确写出的要求，未提及的格式尽量保持原样。
4. 点击“编译为结构化规则”。
5. 查看“规则能力覆盖报告”，尤其留意“需要确认”和“当前无法执行”的内容。

自然语言编译只发送格式要求和精简的结构统计，不发送完整 DOCX 文件。

#### 参考样例提取

适合手上已经有一份“确认排版正确”的 Word 样例，希望把它的可靠格式迁移到当前文档时使用。

1. 切换到“参考样例提取”。
2. 点击“选择合格样例 DOCX”，选择参考文件。参考文件不会替换当前待处理文档。
3. 查看候选摘要中的来源指纹、可靠属性覆盖率、角色映射，以及“待确认与未自动复制内容”。
4. 确认范围符合预期后，点击“确认采用候选规则”。只有执行这一步，高级规则才会切换为候选规则。
5. 如有需要，展开“高级规则 JSON”进一步检查，然后先做格式体检或直接排版。

系统会自动采用各分节一致的页面设置，以及能明确对应正文、主副标题和各级标题的已使用样式。
表格示例、多级编号、页眉页脚、冲突样式、主题字体和未显式声明的样式继承不会被盲目复制，而会
显示为待确认或未覆盖项。候选默认关闭正文自动拆分，避免参考模板意外改变目标文档结构。

参考文件会在本地临时目录中解析，通过安全检查并返回候选后立即清理，不会作为待处理文档保存。
候选采用后可以切换到“我的规则包”保存复用，但这仍不代表参考文件已经成为经过机构审批或认证的
规则包；需要由使用方自行记录适用范围和核对依据。

#### 我的规则包

适合行政、教务、法务等需要把同一套规则稳定用于多份文档的用户。

1. 先通过默认方案、自然语言、参考样例或高级 JSON 准备好当前规则。
2. 切换到“我的规则包”，展开“创建第一个规则包”或“保存当前规则”。
3. 填写名称、具体适用范围和本次变更说明；建议在说明中记录模板来源和未覆盖内容。
4. 点击“另存为新规则包”；之后修改规则时，选择该规则包并点击“保存到所选包的新修订”。
5. 选择任意修订后，可以载入当前文档、导出 `rule-pack.v1` JSON，或将旧修订恢复为一个新的草稿
   修订。恢复不会覆盖或删除已有历史。

如果已经人工核对来源、适用范围和高级规则，可以勾选“标记为本地已确认”并填写核对人、日期和
依据。这个状态只是本机审计记录，不代表单位盖章、第三方认证或法规合规。

规则包保存采用可安全重试的请求标识。如果连接在保存后中断，保持表单内容不变并再次点击同一
按钮即可，系统会返回原修订而不是重复创建。每个修订还保存规则 SHA-256；完整性不一致时会阻止
载入。

要把一个规则修订迁移到另一台电脑：

1. 在来源电脑选中准确修订并点击“导出 JSON”。导出文件只包含该修订，不包含整个版本历史。
2. 在目标电脑展开“从另一台电脑导入规则包”，选择该 `.json` 文件并点击“检查文件”。检查阶段
   不写入规则库。
3. 核对来源名称、修订、适用范围、规则摘要，以及“结构与摘要通过”和“未验证数字签名”提示。
4. 如果本机已有同名规则，系统会建议一个不覆盖现有数据的名称；确认后点击“确认导入为草稿”。
5. 导入完成后先重新核对规则，再明确点击“载入所选修订”。导入动作不会自动改变当前文档的规则。

导入默认只接受不超过 2 MB 的 DocAlign `rule-pack.v1` JSON，并严格校验结构和内嵌规则摘要；篡改、
损坏、扩展名错误或超限文件会被拒绝。完全相同的工件会定位到现有修订，不创建副本；响应丢失后
用同一内容重试也不会重复写入。当前格式没有发布者数字签名，因此来源电脑的“本地已确认”只保留
为追溯信息，目标电脑始终以草稿接收。该流程是显式备份/迁移，不是云同步或机构审批。

#### 自动结构排版

默认开启。系统会识别各级标题，并按手动换行或完整句子边界安全拆分过长正文。包含图片、公式、字段、书签等受保护结构的段落不会被自动拆分。

如果只想调整格式、不想重构正文段落，可以取消勾选。此时主按钮会显示“格式化并验证”。

#### 高级规则 JSON

仅建议熟悉 `FormattingSpec v1` 的用户使用。展开“高级规则 JSON”后可以精确修改规则；如果 JSON 的逗号、引号或括号有误，提交时会提示解析失败。

### 5. 先做格式体检（可选）

点击“只做格式体检”后，系统会按当前规则检查源文档，但不会修改文件，也不会创建格式化任务。

结果会显示偏差数量和位置编号，例如：

- `p3`：正文中的第 3 个段落；
- `s1`：第 1 个分节；
- `t1.r2.c3.p1.r1`：第 1 个表格中第 2 行、第 3 列的具体文字位置。

页面最多展示前 12 项问题，完整结果可通过 API 获取。

### 6. 自动排版并验证

确认规则后，点击“自动排版并验证”（关闭自动结构排版时显示“格式化并验证”）。

系统会在本地后台执行排版，并在完成后重新打开生成的 DOCX，检查内容完整性和格式合规性。任务运行时可以刷新页面；再次打开网站后会自动恢复当前工作区和任务进度。

如果检测到未授权的内容变化或受保护结构被改动，系统会阻止输出，源文件仍保持不变。

### 7. 下载和复核结果

任务完成后，右侧会显示“输出已生成”。可以：

- 先查看“排版结果摘要”，确认格式验证和原文保护是否通过；
- 分别查看“结构段落待确认”和“交付前人工核对”：前者表示结构识别仍需确认的段落，后者来自
  参考包的人工复核、暂不支持条款和人工验收步骤，两者不能互相替代；
- 展开“源文档处理边界”，确认复杂对象的处理方式和位置。输出通过内容保护只证明这些对象没有被
  非预期破坏，不证明文本框、脚注、批注或嵌入对象已经按专门规则排版；
- 查看同一区域中的确认证据。新任务会显示“单文档任务已明确确认”或“批处理策略已明确确认”，并
  保存确认时间和边界快照 SHA-256；旧任务或直接使用内核生成的审计可能明确显示“未记录确认”；
- 使用规范参考包时，确认“目录规则原样执行”。如果高级 JSON 或自动结构排版选项发生变化，之前
  的边界确认会自动撤销；重新执行后，结果页会标记“目录规则已被修改”，原参考包覆盖结论失效；
- 展开“规则交付边界”，核对规范版本、适用范围、公开来源、规则 SHA-256、人工/暂不支持条款及
  人工验收步骤。刷新页面或打开独立任务页后，这些证据仍会恢复；
- 点击“查看格式前后对照”，在同一窗口并排检查源文档与输出文档；两侧默认按阅读进度同步滚动，
  关闭同步后可以分别检查；
- 查看实际格式调整数量，以及页面版式、标题与段落、字体、表格、页眉页脚和视觉清理等改动分布；
- 展开“查看具体改动”，逐项查看位置编号和“原值 → 新值”；可点击的段落或表格编号会返回左侧
  文档结构并高亮对应内容；
- 如果仍有结构待确认段落，点击“查看待确认段落”直接返回对应内容；规则级人工清单需在 Word/WPS
  和正式模板中逐项完成；
- 点击“下载格式化 DOCX”获取新文件；
- 点击“查看审计”查看机器可读的审计结果；
- 点击顶部“导出格式画像”下载源文档的格式画像 JSON。

在前后对照窗口底部也可以逐项查看改动，并点击“回到结构位置”关闭窗口、返回左侧结构列表高亮。
任务刷新恢复后，独立任务页仍可重新打开同一组源文件与输出文件。对照只在本机读取两份 DOCX；
预览会禁用文档中的外部链接和替代 HTML，不会改写源文件。

建议用 Microsoft Word 或其他兼容软件打开下载文件，重点检查分页、字体可用性、宽表、形状、
文本框和图片位置。浏览器中的前后对照属于“最佳努力预览”，不是 Word 的法律黑线、修订记录或
像素级最终效果；机器结论仍以输出 DOCX 的 OOXML 重开验证和审计结果为准。

为了让任务完成后的页面保持轻量，具体改动最多展示前 32 项；完整改动、规则来源快照、执行规则
与目录规则哈希、自动条款、人工条款和验收清单保存在审计 JSON 中，人工审计 Markdown 会列出
规则交付边界及前 50 项改动。位置编号表示确定性的 Word 结构位置，并非像素坐标。

### 8. 批量处理多份文档

批量处理适合行政月报、学生作业、项目材料等“同一套规则、多份独立文件”的场景：

1. 先在单文档工作台把规则保存为“我的规则包”，并记录具体适用范围；建议优先使用“本地已确认”修订。
2. 点击右上角“批量处理”，一次或分多次添加 DOCX。页面会显示文件数与总大小限制。
3. 选择规则包和精确修订版本。整批任务会锁定该不可变修订，之后规则包更新不会改变本批结果。
4. 如果选择草稿修订，必须勾选风险确认；这不表示机构认证或法规合规。
5. 勾选批量复杂内容确认。批处理不会在分析出复杂对象时逐份暂停；确认表示你会根据每份结果中的
   风险标记，在 Word/WPS 中逐份完成交付核对。服务端会保存这项批次策略，未确认不能建立批次。
6. 填写批次名称并开始处理。每个文件独立执行，某个文件损坏或验证失败不会阻止其他文件完成。
7. 页面可安全刷新或关闭；重新打开后会恢复上次批次。短暂断连时页面自动退避重连，任务继续在本机后台运行。
8. 对有源文件记录的失败项可点击“重试失败项”。新尝试不会覆盖旧记录；上传阶段就已损坏的文件不能重试，需要新建批次并重新选择正确文件。
9. 完成后可单独下载 DOCX/审计，或下载 ZIP。ZIP 只包含成功输出，并附带 `batch-audit.json`；失败原因仍保留在批次审计中。
   完成文件若显示“复杂内容 N 类待核对”，应打开该文件的单项审计，按“源文档处理边界”逐类完成
   Word/WPS 人工检查；批量成功状态不替代这一步。
10. 需要提前停止时点击“取消批次”。排队文件立即取消，运行中的文件会完成当前安全阶段后停止；
   已经验证完成的输出仍可下载，未完成输出会被丢弃。
11. 批次结束后可点击“删除本地批次”。确认后会永久清理该批次的源 DOCX、分析、尝试、作业、
    输出和批次审计；共享规则包不会被删除。

批次创建和单项重试都可安全重复提交。如果响应返回前连接中断，保持文件与表单不变再次点击即可；
服务端会复用原请求，不会重复建批。当前批量能力是单机本地队列，不包含文件夹自动监控、多人协作
或正式审批流。

## 四、数据与隐私

- 上传文件、分析结果、规则、任务、批次、尝试历史和输出默认保存在本机 `DOCALIGN_DATA_DIR`。
- 源 DOCX 不会被直接覆盖，排版结果始终生成新文件。
- 点击“删除本地文档”会删除当前文档及其分析、临时规则、任务和输出，且不可撤销。
- 点击“删除本地批次”会精确删除该批次及全部关联文档和产物，且不可撤销；活动批次必须先取消并
  等待安全停止。
- “我的规则包”是跨文档独立保存的数据，不会随当前文档删除；可导出单个修订，在另一台电脑先
  检查再导入。导入不等于自动同步，若要完整迁移全部历史，应在关闭应用后备份整个数据目录。
- “智能分析”仅在用户确认后发送段落文字和格式摘要。
- “自然语言编译”只发送格式要求和精简结构统计。
- “参考样例提取”完全在本地临时解析，候选返回后立即清理参考文件。
- 密钥只由后端环境读取，不进入浏览器、SQLite 或审计日志。

## 五、常见问题

### 页面提示“无法连接本地排版服务”

确认 API 和网站都已启动，然后点击页面中的“重试连接”。还可以访问 <http://127.0.0.1:8000/api/v1/health> 检查 API；正常时会返回 `status: ok`。

如果 API 能启动但问题反复出现，进入“设置”运行本机诊断。如果网站或 API 均无法打开，在项目目录
执行 `uv run python -m scripts.diagnose --out docalign-support-diagnostic.json`。不要直接发送 `.env`、
数据库、源 DOCX 或原始日志。

### 按钮是灰色的

- “分析结构”需要先上传或创建文档；
- “智能分析”需要先配置兼容模型；
- “编译为结构化规则”需要先完成分析、填写自然语言要求并配置模型；
- 排版任务运行期间，体检和重复提交按钮会暂时禁用。

### 预览显示不完整或与 Word 不一致

这是浏览器预览能力的限制。请下载 DOCX，并以 Word 中的显示和审计结果为准。

### 上传失败

确认文件扩展名为 `.docx`、文件未损坏且没有超过页面显示的大小限制。旧版 `.doc` 文件需要先在 Word 中另存为 `.docx`。

### 排版或验证失败

根据页面提示检查规则冲突、表格格式或内容保护问题。自然语言规则可以重新编译，高级 JSON 应先检查语法。失败不会覆盖源文件。

## 六、设置页面

点击右上角“设置”可以查看：

- DocAlign 当前总占用、可回收空间与本机磁盘余量；
- 源 DOCX、分析、任务审计、输出、批次包、数据库等分类占用；
- 文档、分析、任务、批次和规则包的本地记录数量；
- 数据库、版本、目录权限、磁盘和本地产物诊断；
- 当前 API 地址；
- 是否启用本地处理；
- 兼容模型是否已配置；
- 当前上传大小限制；
- 桌面分发版的“安全退出应用”入口。关闭浏览器页面只会隐藏界面，不会停止后台任务；安全退出会
  等待任务收尾、关闭数据库和本地服务，不会删除源文件、规则或结果。

“可清理项目”分为两类：

- **已结束批次**：点击“删除”会清理该批次的源文件、分析、任务、输出和批次审计，规则包保留；
- **独立文档**：点击“删除”会清理该文档及其分析、任务和输出。正在处理的项目显示“处理中”，
  必须等待任务结束后才能删除。

每次删除前都会再次确认，删除不可撤销。DocAlign 默认不设置自动过期时间，不会仅因文件较旧就
自行清理；页面显示的“可回收”是候选项目的估算总量，不代表已经释放的空间。存储清单不展示正文
或完整本地路径。如果设置页提示磁盘空间不足，应先下载并备份仍需保留的结果，再删除不需要的项目。

点击“运行诊断”后，页面按“通过 / 关注 / 失败”列出检查结果和处理建议。“下载安全诊断 JSON”只在
本机生成文件，不会自动上传。报告明确排除正文、文件名、记录 ID、完整路径、数据库连接串、模型
端点、密钥和原始日志；请先自行打开检查，再决定是否提供给支持人员。

开发环境的模型端点和密钥由管理员在项目根目录的 `.env` 中配置；桌面分发版只读取启动进程的系统
环境变量，不会读取启动目录里的 `.env`。修改配置后需要重启 DocAlign。
